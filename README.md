# Ладен — сайт-визитка и запись на занятия

Сайт репетитора по истории: визитка, публичный календарь свободного времени,
форма заявки и админ-панель. Русский и азербайджанский языки, mobile-first.

**Стек:** Next.js 16 (App Router) · Tailwind CSS 4 · Supabase (Postgres) · Telegram Bot API
**Хостинг:** Vercel. Всё работает в рамках бесплатных тиров — платных сервисов нет.

---

## 1. Что нужно сделать перед запуском

### 1.1. Заполнить контакты и цены

Единственный файл с «человеческими» данными — [`src/lib/site-config.ts`](src/lib/site-config.ts).
Там плейсхолдеры, которые нужно заменить:

| Поле | Что указать |
| --- | --- |
| `photo` | путь к фото, если положить файл в `public/` (например `"/laden.jpg"`); пока `null` — показывается заглушка с буквой имени |
| `contacts.phone` | телефон |
| `contacts.telegram` | username **без** `@` |
| `contacts.whatsapp` | номер в международном формате без `+` и пробелов |
| `contacts.email` | email |
| `prices.individual` / `prices.group` | цена за занятие |
| `prices.lessonDuration` / `prices.lessonsPerWeek` | длительность занятия и максимум занятий в неделю |
| `trial.isFree` | `true` — пробное бесплатное, `false` — платное (тогда заполнить `trial.price`) |

**Требуют уточнения у Ладен** (сейчас стоят плейсхолдеры):
цены индивидуальных и групповых занятий, условия пробного занятия (бесплатно/платно),
реальные контакты. Пока условия пробного не подтверждены, под блоком выводится строка
«Условия пробного занятия уточняются…» — её текст лежит в `i18n.ts` (`formats.trial.note`),
удалите ссылку на неё в [`src/components/Formats.tsx`](src/components/Formats.tsx), когда данные будут точными.

Весь остальной текст сайта — в [`src/lib/i18n.ts`](src/lib/i18n.ts), двумя языками рядом.
Азербайджанское написание имени (`Lədən`) стоит проверить у Ладен.

### 1.2. Создать базу в Supabase

1. Зарегистрироваться на [supabase.com](https://supabase.com), создать бесплатный проект.
2. Открыть **SQL Editor → New query**, вставить содержимое
   [`supabase/schema.sql`](supabase/schema.sql) и выполнить.
3. Скопировать из **Project Settings → API**: `Project URL` и ключи.

Скрипт создаёт таблицы `applications` и `availability`, индексы и политики RLS.
В конце файла — два варианта доступа для админки; рекомендуемый (**Option A**)
не требует ничего дополнительно, достаточно задать `SUPABASE_SERVICE_ROLE_KEY`.

### 1.3. Создать Telegram-бота

1. Написать [@BotFather](https://t.me/BotFather) → `/newbot` → получить токен.
2. Написать своему боту любое сообщение (иначе он не сможет писать первым).
3. Открыть `https://api.telegram.org/bot<ТОКЕН>/getUpdates` и взять
   `result[0].message.chat.id` — это `TELEGRAM_CHAT_ID`.

## 2. Переменные окружения

Список и описание — в [`.env.example`](.env.example). Для локальной разработки
скопируйте его в `.env.local`.

| Переменная | Обязательна | Назначение |
| --- | --- | --- |
| `SUPABASE_URL` | да | URL проекта Supabase |
| `SUPABASE_ANON_KEY` | да | публичный ключ |
| `SUPABASE_SERVICE_ROLE_KEY` | нет, но рекомендуется | ключ для серверных операций админки; если задан, используется вместо anon |
| `TELEGRAM_BOT_TOKEN` | нет | без него заявки сохраняются, но уведомления не приходят |
| `TELEGRAM_CHAT_ID` | нет | то же |
| `ADMIN_PASSWORD` | да | пароль входа в `/admin` |

Ни одна переменная **не** имеет префикса `NEXT_PUBLIC_` — все ключи и пароль
остаются на сервере и не попадают в код страниц.

## 3. Локальный запуск

```bash
npm install
```

Затем скопируйте `.env.example` в `.env.local`, заполните значения и запустите:

```bash
npm run dev
```

Сайт откроется на http://localhost:3000 (корень редиректит на `/ru` или `/az`
по заголовку `Accept-Language`).

Проверка сборки и типов:

```bash
npm run build
```

---

## 4. Деплой на Vercel

1. Залить код в репозиторий GitHub.
2. На [vercel.com](https://vercel.com) → **Add New → Project** → выбрать репозиторий.
   Next.js определяется автоматически, настройки сборки менять не нужно.
3. В **Settings → Environment Variables** добавить все переменные из таблицы выше
   (для окружений Production и Preview).
4. **Deploy**.

После деплоя админка доступна по адресу `https://<ваш-домен>/admin`.

## 5. Как всё устроено

### Публичная часть — одна страница с разделами

`/ru` и `/az`, обе версии предгенерированы статически:

| Раздел | Якорь | Файл |
| --- | --- | --- |
| О преподавателе | `#about` | [`Hero.tsx`](src/components/Hero.tsx) |
| Форматы, цены, пробное занятие | `#formats` | [`Formats.tsx`](src/components/Formats.tsx) |
| Календарь свободного времени | `#schedule` | [`AvailabilityCalendar.tsx`](src/components/AvailabilityCalendar.tsx) |
| Форма заявки | `#apply` | [`ApplicationForm.tsx`](src/components/ApplicationForm.tsx) |
| Контакты | `#contacts` | [`Contacts.tsx`](src/components/Contacts.tsx) |

Календарь — **информационный блок, а не бронирование**: интервалы не кликаются,
слоты не «занимаются». Ученик смотрит на него и пишет удобное время текстом в заявке.
На телефоне это список дней, на широком экране — сетка из семи колонок.

### Обработка заявки

`POST /api/applications` ([route.ts](src/app/api/applications/route.ts)):

1. Валидация на сервере ([`validation.ts`](src/lib/validation.ts)) — клиентская
   проверка есть, но она только для UX, доверять ей нельзя.
2. Запись в таблицу `applications`.
3. Уведомление в Telegram со всеми полями заявки читаемым текстом
   ([`telegram.ts`](src/lib/telegram.ts)).

Если Telegram недоступен, заявка **всё равно сохранена**, а ученик видит успех —
падение уведомления не должно терять заявку. Ошибка пишется в логи Vercel.

### Админка `/admin`

* Пароль сравнивается только на сервере, в `POST /api/admin/login`. Клиент получает
  подписанную (HMAC-SHA256) httpOnly-cookie на 12 часов — самого пароля в ней нет.
* Доступ закрывает [`src/proxy.ts`](src/proxy.ts) (в Next 16 это бывший
  `middleware.ts`): неавторизованных редиректит на `/admin/login`, а запросы к
  `/api/admin/*` отклоняет с 401. Каждая защищённая страница и ручка дополнительно
  проверяет сессию сама.
* **Заявки** — таблица, сортировка по новым, фильтры «все / в ожидании / обработанные»,
  переключение статуса. На телефоне вместо таблицы карточки.
* **Свободное время** — добавление и удаление интервалов (день недели, «с»–«до»,
  формат, заметка). После изменения публичные страницы сбрасывают кэш и показывают
  новое расписание сразу.

Админка не индексируется поисковиками (`robots: noindex`).

## 6. Что проверено, а что нет

Проверено локально: обе языковые версии и переключатель, редирект с корня,
mobile- и desktop-раскладки, условные поля формы, серверная валидация,
сохранение заявки, рендеринг календаря, вход и выход из админки, отказ в доступе
без сессии (307 для страниц, 401 для API), список заявок, добавление и удаление
интервалов, корректная деградация при недоступном Telegram.

DB-зависимые пути проверялись на локальном моке Supabase REST, а не на живом
проекте — **после создания настоящего проекта Supabase стоит один раз пройти
сценарий вручную**: отправить тестовую заявку, увидеть её в `/admin` и получить
сообщение в Telegram.
